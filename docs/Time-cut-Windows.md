# Time-cut 本地相簿 · Windows 测试版

解压整个压缩包，双击同一目录中的 **Time-cut.exe**。程序使用 Windows x64 和 Microsoft Edge WebView2。首次打开后在“导入照片与视频”中选择一个用来存放原件的普通文件夹，点击“保存图库”。推荐选一个空的专用文件夹，已有照片的图库也可以使用。

## 用数据线归档

手机自动导入读取 USB 可见的常规相册目录。安卓包括各存储卷的 `DCIM`、`Pictures`、`Movies` 及其子目录，iPhone 读取 `DCIM` 相机目录。安卓会跳过以点开头的隐藏项及 `Android/data` 等应用私有目录。要导入下载目录、`Android/media` 或其他位置的媒体，可先复制到电脑，再使用“本地文件夹”导入。

1. 在“手机插线导入”中开启“自动导入”。安卓解锁后将 USB 用途设为“文件传输”。图像传输模式可能只公开相机内容。
2. iPhone 按系统提示解锁并“信任这台电脑”。Time-cut 可以从 Windows 照片接口接收，也可以通过 Apple 官方的「Apple 设备」读取已配对手机的相机原件。若希望保留 HEIC / HEVC 原始格式，在手机照片设置中将“传输到 Mac 或 PC”设为“保留原片”。如果 Windows 将已有 HEIF 原片列为相同设备标识、相同修改时间的 JPEG，界面会列出这批待核对项，程序先接收其他缺少的原件。仅在 iCloud 中保存的原件须先下载。
3. 连接后，首次接收会优先写入第一份新原件。程序逐个目录把照片、视频和 AAE、XMP 附件列在本地清单里。盘点期间窗口显示已保存几个目录、列出多少项。一个目录发生读取错误后，重试会优先盘点其他目录并接收其中的新文件。取得相册文件清单后，窗口显示总数、已有备份凭据和待核对的数量。Apple 原件通道提供源端摘要时，可校验后复用电脑上的副本。Windows WPD 通道缺少源端摘要时，复扫会重新读取手机文件核对内容；大图库需要保持连接更久。中断后保留清单和接收凭据，未传完的单个文件重新读取。
4. 看到 **相册原件已收齐，可以拔线** 就可以断开手机。此时清单上的每一项都有已校验的本地文件，程序也已重新核对手机的目录成员和文件版本，历史待补记录已清零。空目录、缺少已见项目的清单或复制期间发生的变化都会保留为待核对。窗口显示收齐时间和本轮实际经过时间。此后电脑按拍摄年月归档、合并重复内容、配对实况照片和编辑附件，并更新本机相册索引。关闭主窗口可在托盘继续。请在本地整理结束前保留图库中的 `.time-cut` 目录。

Windows 仍显示手机但读不到照片时，应用会保留上次的目录清单和每份原件的接收记录。通过 USB 导出的照片和视频有时会改变编码。应用会单列有对应 HEIF 原片的 JPEG，以及标识、文件名、修改时间相同但大小改变的 MOV。如果这批待核对文件的预计总量超过图库可用空间，界面会显示两个数值。接收器暂缓写入这批文件，继续补其他原件。后续盘点会重新检查手机提供的格式和磁盘空间。

目录扫描中断时，已经完整收到的文件会保留。相簿会把本轮接收记录与上次完整清单逐项核对。设备、文件路径、版本、大小和修改时间均吻合，条目能唯一确定，本地文件也通过内容校验时，界面会显示从现有备份确认了多少项。这一步可以在手机离线时完成。确认相册原件收齐还需要连接手机，重新核对相册目录。

若电脑已有 Apple 设备服务，开启自动导入后，即使资源管理器暂时看不到 iPhone，图库也能通过它读取已配对手机的 DCIM 相机目录。应用用手机提供的内容摘要复用已校验的本地备份，补收缺少的内容。遇到不支持返回摘要的手机，程序会读取原件进行核对。Windows 清单和 Apple 相机目录可能包含同一份文件，面板分别显示进度。

如果面板显示“Apple 相机目录暂时无法读取”，保留原来的图库并让自动导入继续运行。“本地累计保存”显示已取得凭据的来源条目。目录恢复可读后，应用会接着补收。若「Apple 设备」也提示“未能读取 iPhone 的内容”，其中的“恢复”是恢复出厂设置，会抹掉手机。请保留现有数据，等相簿明确显示“相册原件已收齐，可以拔线”再断开手机。

## 导入电脑上的照片

打开顶部“导入照片与视频”，选择本地文件夹，点击“开始导入”。默认将原件复制到图库。更换原件图库时，先点击“更改”，选好目录，再点击“保存图库”。选择“仅索引原位置”后点击“加入相册”，该目录的原件保留在原处。如果原位置和图库各有一份相同照片，“所有文件”可以同时列出两条记录，重复导入仍只在受管图库中保留一份原件。

## 检查结果

图库中可直接打开按年、月存放的原件。归档优先采用照片或视频内的拍摄时间，缺少拍摄时间时采用来源文件的修改时间，两者都无法确定时归入“日期未知”。带 GPS 坐标的原片可用于地点浏览。内容相同的照片跨来源只存一份，同名异图保留两份。重复连接或重新导入同一批不变的素材，预期新增为零。原件与导入记录保存成功后，图库会继续生成预览和搜索索引。导入器以只读方式访问手机和来源目录。

XMP 和 AAE 编辑信息保存在各自原件旁。两张不同照片使用相同的编辑参数时，各自保留一份可独立修改的伴随文件。再次导入同一张照片及其伴随文件，新增仍为零。

## 浏览和整理

- 在「日历」按拍摄年月日浏览，在图库顶部选择按拍摄日期分组可展开时间线。
- 「地点」根据原件 GPS 在本机查找附近城镇并按国家、地区、地点组织。地点取决于原件是否包含有效坐标。
- 「人物」在本机检测并分组照片中的面孔。可以给相册命名，之后导入相似的面孔时会沿用既有相册。人物名称由用户填写。
- 「内容分类」在本机整理旅行记忆、工作记录、网图与截图和日常记录。模型把不确定的内容放在「待确认」，其中符合手机屏幕比例的竖版 PNG 会再检查常见的应用界面。打开照片详情可手动更正分类，也可恢复自动结果。
- 若已安装 Codex 或 Claude Code 并可从系统 PATH 启动，可在照片详情中打开「使用 AI 工具建议分类」，选择工具后点「发送预览」。工具可能用你的账号联网处理一张去除拍摄元数据的压缩预览。收到建议后可决定是否采用。

图库中的 `.time-cut` 保存导入记录和中转文件，复制或备份整座图库时一起保留。导入照片时请选择图库目录或照片所在的子目录。浏览索引、人物和分类设置默认位于 `%LOCALAPPDATA%\app.timecut.album`，备份时一并保留。

Windows 测试覆盖了文件夹导入、跨来源去重、同名异图、HEIC 缩略图和苹果实况照片配对。进程中断测试在一个约 384 MiB 的视频写入途中结束了程序，重启后补入的视频与源文件校验和一致。2026 年 11 月 23 日，在一台实体 iPhone 的接收测试中，Windows 共列出 68 个目录、47,782 项照片、视频和附件。对原有图库和收件区逐份计算内容摘要，确认其中 5,445 份不同内容是这次新增的，共 17.79 GB。相册导入验收还需清单中的每个条目都有本地原件、历史待补项得到核对，并在同一台手机上复扫得到零新增、零失败。

### 一次可以自己重复的插线测试

1. 先选一个专用图库，接上已解锁的手机。确认窗口显示手机名称，等“新接收”出现第一份原件，再在一段较大的视频传输中拔线。
2. 插回同一部手机，保持解锁。应用会沿用先前的收件记录。等到“相册原件已收齐，可以拔线”后断开手机，在电脑上等待本地整理完成，然后打开照片和视频检查。
3. 如需复查去重，可在手机连接时点“重新检测”。素材未变化时，新接收应为 0，已有备份数应与当次发现的素材数相同。把手机上的一张原片通过文件夹再次导入，内容完全相同也应显示“新增 0”。手机以不同格式导出时，内容会变化，图库会保留两份。
4. 若相簿没有开始接收，查看 Windows 资源管理器能否打开照片目录，或「Apple 设备」能否识别这台 iPhone。在相簿中点“重新检测”可立即重试。反馈时可提供 Windows 版本、手机型号、连接模式以及“最近导入记录”中的错误文字。

## 版本与源码

Time-cut 的 Windows 测试版基于 Lap v0.4.1，固定提交 `f92b0b032c9ea317c3f499a65efee69d04203b5e`。许可证及第三方说明随包放在 `licenses`。本版随附 CLIP、OpenCV Zoo YuNet 和 SFace、FFmpeg 与 ONNX Runtime。Windows 自动接收使用微软 WPD 的 MTP / PTP 只读设备流。原件可直接用资源管理器浏览。

[Lap 源码](https://github.com/julyx10/lap/tree/v0.4.1) · [Apple 导入说明](https://support.apple.com/zh-cn/120267) · [Android 文件传输](https://support.google.com/android/answer/9064445?hl=zh-Hans)

### 从本地源码构建

在 Visual Studio 2022 的 x64 Developer PowerShell 中使用 Rust MSVC、CMake 3.31、Node.js 和 pnpm 9。准备脚本按 NuGet 的 SHA-512 核对 Microsoft.ML.OnnxRuntime 1.22.0，并取出 x64 库及许可。已有该版本的 NuGet 包时，可传入 `-Package <nupkg 路径>` 离线使用。从本项目根目录执行以下命令。

```powershell
git submodule update --init --recursive
$env:ORT_LIB_LOCATION = Join-Path $PWD '.timecut-build/onnxruntime-win-x64-1.22.0'
.\scripts\prepare_windows_ort.ps1 -Destination $env:ORT_LIB_LOCATION
$env:Path = "$env:ORT_LIB_LOCATION;$env:Path"
.\scripts\download_models.ps1
.\scripts\download_ffmpeg_sidecar.ps1 -Arch x64
pnpm --dir src-vite install --frozen-lockfile
pnpm --dir src-vite build
$env:ORT_PREFER_DYNAMIC_LINK = '1'
$env:LAP_JPEG_NO_SIMD = '1'
cargo build --locked --release --manifest-path src-tauri/Cargo.toml
.\scripts\package_timecut_windows.ps1
```

生成的便携目录、ZIP 和同名 `.sha256` 校验文件位于项目的 `release-test`。可用 `-OutputDirectory <目录>` 指定其他输出位置。同版本重打包会复用完全相同的展开目录；若内容不同，先保留上份目录，再发布干净的新目录。每个新包从干净目录组装，并在包内 `BUILD-INFO.json` 记录打包时的 Git 提交、工作树是否有修改、子模块提交和程序的 SHA-256。

GitHub 的 **Time-cut Windows x64** 工作流在拉取请求和手动运行时生成可下载的候选产物。推送与源码版本一致的 `timecut-v<版本>` 标签会从该提交构建 ZIP、校验解压后的程序并运行桌面及恢复测试，通过后将 ZIP 和 SHA-256 附到该仓库的同标签 Release。此工作流发布 x64 便携版。

导入核心测试可用 `cargo test --release --manifest-path src-tauri/Cargo.toml ingest::` 运行。

使用 Node.js 24 可复跑桌面和中断恢复测试。先从托盘退出日常使用的 Time-cut。在源码根目录执行 `node scripts/test_timecut_desktop.mjs <已解压的程序路径>` 和 `node scripts/test_timecut_recovery.mjs <已解压的程序路径>`。两个脚本都在项目的 `.timecut-build` 内建立独立测试目录。桌面脚本可追加一组苹果实况照片的图片和 MOV 路径来检查配对。[本次使用的公开实况样本](https://github.com/pulsejet/memories/tree/504243ba5eb07cf29770e5802ca91874e960e681/tests/assets)

在已连接并授权的单台 iPhone 上，可运行 `node scripts/test_timecut_iphone.mjs <已解压的程序路径>`。它在 `.timecut-build` 中建立独立图库，复制 USB 可访问的 DCIM 相机原件及其附件，然后在同一次连接上复扫并验证去重。它会保留归档和图库索引，结果文件只记录耗时及数量。

中断后可在程序路径后追加原测试目录，沿用已有归档继续验收。再加 `--verify-local` 时，脚本逐份读回归档原件核对 BLAKE3，检查媒体是否已录入指定相册，并统计分类和人脸处理记录。结果写入测试目录的 `local-verification.json`，沿用原来的自动接收设置。只检查归档原件可以运行 `Time-cut.exe --verify-archive "图库绝对路径"`。原件为空、缺失或内容不符时，命令会返回非零退出码。

### 独立核对 iPhone 相机原件

Windows 反复中断时，自动接收会在恢复过程中为尚未列出的目录安排专门的盘点机会。每个完整目录的清单会保存在所选图库中。

Apple 原件通道重新可用时，相簿优先接收新发现的照片和视频，单个附件暂时读不到会留待补查。如果目录一时打不开，相簿还会尝试上一次清单里已知路径的未收文件。导入窗口显示本次查到的数量、累计已保存的接收记录和下次自动重试时间。可以保持连接去做别的事，等相簿提示「相册原件已收齐，可以拔线」。

在电脑上运行 `Time-cut.exe --index-original-checksums "图库绝对路径"` 可为历史备份建立内容指纹。它在本地读取文件并核对原有 BLAKE3 摘要，保存进度，随后可以接着运行。

已安装 Apple 设备并完成 USB 配对的电脑，可以运行 `Time-cut.exe --check-iphone-originals "图库绝对路径"`。程序读取 iPhone 的 DCIM 目录，把手机端的文件摘要、大小和电脑上已确认的原件逐项对应，然后再次枚举目录。结果中的 `listed` 是本次列出的条目数，`matched` 是已找到本地原件的数量，`without_local_proof` 是仍需查证的数量。只有两次枚举一致才会出现 `stable_inventory: true`。这份核对记录和自动接收记录分别保存在图库的 `.time-cut` 内。
